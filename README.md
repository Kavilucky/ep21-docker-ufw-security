# Docker + UFW: порт закрыт, а база открыта

Набор для подписчиков канала [@ByteAutomate_AI](https://t.me/ByteAutomate_AI): скрипт аудита сервера и эталонный `docker-compose.secure.yml`. Разбор уязвимости связки Docker и UFW с примерами.

## В чём проблема простыми словами
Вы включили файрвол UFW, порт базы данных «закрыт». Но если контейнер запущен с `-p 5432:5432` (или в Compose `ports: ["5432:5432"]`), Docker сам добавляет правило в таблицу `nat`, цепочку `PREROUTING`, и перенаправляет пакеты прямо в контейнер. Пакет идёт через цепочку `FORWARD` и не заходит в `INPUT`, где работает UFW. Итог: `ufw status` показывает порт закрытым, а из интернета он доступен. Это описано в документации Docker (раздел Docker and ufw): https://docs.docker.com/engine/network/packet-filtering-firewalls/

Если адрес не указан, порт публикуется на всех интерфейсах (`0.0.0.0`). Поисковик Shodan индексирует такие открытые порты, а боты сканируют их сами.

## Что в архиве
| Файл | Назначение |
|---|---|
| `audit-docker-ufw.sh` | Аудит сервера. Читает `ufw status`, `iptables -t nat -L DOCKER -n -v`, `ss -tulnp`. Ничего не меняет и не отправляет. Выводит `[CRITICAL EXPOSED]`, `[SAFE LOCAL]` и готовые команды исправления. |
| `docker-compose.secure.yml` | Эталон с тремя уровнями защиты: привязка к `127.0.0.1`, сеть базы `internal: true`, сайт через Cloudflare Tunnel без открытых портов 80 и 443. |
| `README.md` | Это руководство. |

## Запуск аудита одной строкой
Нужен Linux-сервер с Docker; права root нужны для чтения `iptables`.

```bash
curl -fsSL https://raw.githubusercontent.com/Kavilucky/ep21-docker-ufw-security/main/audit-docker-ufw.sh -o audit-docker-ufw.sh && sudo bash audit-docker-ufw.sh
```

Если файл уже у вас из архива: `sudo bash audit-docker-ufw.sh` (при необходимости `chmod +x audit-docker-ufw.sh`). Для логов без цвета добавьте `--no-color`. Скрипт прочитайте перед запуском: он короткий и только читает. Исходники и история: https://github.com/Kavilucky/ep21-docker-ufw-security.

Код возврата: `0` критичных портов нет, `1` найдены критичные, `2` не хватает прав или утилит.

## Как читать результат
- `[CRITICAL EXPOSED]` порт привязан к `0.0.0.0` (доступен из интернета в обход UFW). Для баз данных и админ-портов (5432, 3306, 6379, 27017, 9200, 2375 и других) это критично.
- `[SAFE LOCAL]` порт привязан к `127.0.0.1`, виден только самому серверу.
- `[WARNING]` внимания требует: например, веб на `0.0.0.0` или выключенный UFW.
- Строка `FIX:` содержит конкретную команду или правку.

## Три уровня защиты (docker-compose.secure.yml)
1. **Адрес `127.0.0.1` в публикации порта.** `ports: ["127.0.0.1:5432:5432"]` вместо `"5432:5432"`. Удалённый доступ к админке: SSH-туннель или WireGuard.
2. **Сеть базы `internal: true`.** У базы нет блока `ports`, к ней нельзя подключиться снаружи, и сама она не выходит в интернет.
3. **Cloudflare Tunnel для сайта.** Контейнер `cloudflared` сам устанавливает исходящее соединение с Cloudflare, поэтому 80 и 443 на сервере наружу не открываются. Без подписки: нужен только аккаунт Cloudflare, условия тарифа проверяйте на сайте сервиса.

Срочная мера, пока вы правите compose: `iptables -I DOCKER-USER -i <внешний интерфейс> -p tcp -m conntrack --ctorigdstport <порт> --ctdir ORIGINAL -j DROP`. Цепочка `DOCKER-USER` проверяется до правил Docker. Правила `iptables` пропадают после перезагрузки без `netfilter-persistent`.

## Бэкап по правилу 3-2-1 (до любых изменений)
Три копии данных, на двух разных носителях, одна вне сервера. Копия на том же диске второй копией не считается. Оригиналы не удаляйте, пока копию не проверили восстановлением.

## Честные ограничения
- Скрипт проверен на синтаксис (`bash -n`) и на подставных выводах `ufw`, `iptables`, `ss`. **Живой запуск на сервере с Docker автором не выполнялся**; проверьте результат сами.
- Проверяется IPv4-таблица `nat`; IPv6 виден только в `ss`. Системы на чистом `nftables`, Podman и rootless Docker не проверялись.
- Аудит видит локальные правила. Надёжная проверка: сканирование снаружи (`nmap -Pn -p 5432 <адрес сервера>` с другого хоста).
- `docker-compose.secure.yml` проверен как YAML, `docker compose config` и реальный запуск не выполнялись. Образы `web` и `db` замените своими и закрепите версии.
- Цифры в видео про 18 минут и выкуп 0,1 BTC на экране подписаны «пример» и не являются замером. Документированный случай: исследователи Border0 в 2024 году оставили открытый PostgreSQL со слабым логином, бот добрался до него за часы, удалил базы и оставил записку о выкупе (Help Net Security, 2024-01-18); платёж данные не вернул.
